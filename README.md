# it_release_bot — запуск в Bothost

Готовое содержимое отдельного репозитория. Сайт: https://release-control.soluchen1988.chatgpt.site

## Загрузка на GitHub
1. Создайте новый репозиторий it-release-bot (предпочтительно Private).
2. Распакуйте архив. Загрузите содержимое папки через Upload files и сохраните Commit changes.
3. index.js, package.json, bothost.json, Dockerfile должны лежать в корне репозитория; папки bot и lib — рядом. Не загружайте сам ZIP вместо файлов.
4. Передайте ссылку на репозиторий для следующего шага настройки.

## Bothost
Создайте отдельный сервис для @it_release_bot и подключите этот репозиторий. Для приватного репозитория Bothost потребуется доступ к нему.
Node.js 22 или новее; точка входа index.js; команда npm start. Внешних зависимостей нет. В комплекте также Dockerfile.
Один постоянно работающий экземпляр, long polling; входящий порт не нужен.

## Переменные окружения
- BOT_TOKEN: токен @it_release_bot из BotFather (или TELEGRAM_BOT_TOKEN; если заданы оба, приоритет у TELEGRAM_BOT_TOKEN).
- TELEGRAM_BOT_USERNAME: it_release_bot
- SITE_URL: https://release-control.soluchen1988.chatgpt.site
- BOT_BRIDGE_KEY: общий секрет не короче 32 символов, одинаковый в Bothost и на сайте.
- SITES_SERVICE_TOKEN: сервисный ключ доступа именно к приватной доске.

Токен и ключи вводятся только в настройках сервисов. Их нет в архиве. Не загружайте их в GitHub и не присылайте в чат.
На сайте имя бота уже задано. BOT_BRIDGE_KEY и доступ сервиса требуют отдельной настройки; после изменения настроек сайта нужна публикация.
До настройки всех переменных бот не заработает. Загрузка кода сама по себе не запускает бота.

## После настройки
Откройте раздел Telegram на доске, создайте одноразовую ссылку привязки, откройте её и нажмите Start. Проверьте сводку релизов.
Runner проверяет имя бота до чтения обновлений. При существующем webhook он остановится и не удалит его автоматически.
Доступ пользователей к приватному сайту и роли настраиваются отдельно. Привязка Telegram не даёт автоматически доступ к сайту.
